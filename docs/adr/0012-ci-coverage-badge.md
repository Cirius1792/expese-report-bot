# ADR 0012: CI Coverage Badge + Tests Badge

**Date:** 2026-09-27
**Status:** Accepted

## Context

The README should surface two live signals without requiring any third-party
service or credentials:

1. A **tests** badge showing the CI workflow status.
2. A **coverage** badge reflecting real coverage of the `expense_report` package.

We follow the pattern used by [pylocc](https://github.com/Cirius1792/pylocc): the
tests badge is the native GitHub Actions workflow badge (zero code), and the
coverage badge is a `coverage.svg` committed to the repo root and regenerated by
CI on every push to `main`.

## Decision

- **Tests badge** — README links to the native workflow badge URL
  `https://github.com/<owner>/<repo>/actions/workflows/ci.yml/badge.svg`.
  GitHub generates this automatically for any workflow file at
  `/actions/workflows/<file>.yml/badge.svg`.
- **Coverage badge** — README links to
  `https://raw.githubusercontent.com/<owner>/<repo>/refs/heads/main/coverage.svg`.
- **Coverage pipeline** (in `.github/workflows/ci.yml`):
  - `unit-tests` runs `uv run pytest --cov=expense_report` and uploads `.coverage`
    as artifact `coverage-data` (`include-hidden-files: true`).
  - New `generate-badge` job depends on `bdd-tests`, runs only on
    `push` to `refs/heads/main`, has `permissions: contents: write`, downloads the
    artifact, installs `coverage-badge` locally, writes `coverage.svg -f`, and
    commits it via `stefanzweifel/git-auto-commit-action@v4` with message
    `"docs: update coverage badge"`.
- **Dependencies** — `pytest-cov` added to the `[dependency-groups] dev` group
  (it pulls in `coverage`, which produces `.coverage`). `coverage-badge` itself is
  **not** a project dependency — installed inside the CI job only.
- **`coverage-badge` requires `pkg_resources`** (imported at module load), which was
  removed from `setuptools` in v81. `uv sync` installs `setuptools` 84 by default, so
  the CI `generate-badge` step pins `setuptools<81` when installing
  `coverage-badge`. This is the only deviation from a literal pylocc port; it is
  required for the badge job to run at all. `coverage-badge` itself remains a CI-only
  install, never a project dependency.
- **Badge placement** — centered block directly below the `<h1>` heading, before
  the intro paragraph, matching the README's existing centered style.

## Rationale

- No external service, no tokens — the badge always reflects the real state of the
  `main` branch.
- `generate-badge` is gated on `push` to `main` (not PR heads) so it never attempts
  an auto-commit against a fork/PR ref.
- `generate-badge` depends on `bdd-tests` so the badge only advances when the
  **entire** CI pipeline is green.

## Consequences

- `coverage.svg` appears on `main` after the first successful `generate-badge` run;
  the tests badge renders once CI runs. Both are inherent to the mechanism, not
  defects.
- `ci.yml` is kept as-is (no rename); `bdd-tests` behavior is unchanged.
- `coverage.svg` must not be committed on feature branches.

## Out of scope

- Third-party coverage services (Codecov, Coveralls, …).
- README branding changes.
- Any `src/` changes.
